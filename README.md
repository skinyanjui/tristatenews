# Tri-State News

Hourly local news from Evansville, Owensboro, Madisonville, Carbondale, Marion, Vincennes and the towns between them. Weather for Evansville sits in the top nav.

## Deploy

1. Unzip, then from this folder run `npx vercel deploy --prod` (log in when asked).
2. Open the URL Vercel prints. No build step, no dependencies.

## How it works

- `api/news.js` fetches every feed in `SOURCES`, drops AP wire copy, keeps only regional stories from wider-market stations (`geo: true`), removes duplicates, and returns one list. The same filters (wire, region, obituary, out-of-area, standing pages) run again on stored stories each time the snapshot is built, so a filter change cleans stories already saved. The news feed keeps up to 240 stories; Police & courts (80), events and obituaries have their own limits, so a busy news day can't push out a sheriff's post that is still in its window.
- The response is cached at the edge for one hour (`s-maxage=3600`), so the feeds are re-pulled about once an hour. An open page also re-checks every hour.
- `public/index.html` is the page. Headlines open the original article in a new tab. Weather comes from Open-Meteo.
- A source that fails or returns nothing is hidden automatically.

## API paths and Vercel functions
Vercel's Hobby plan allows 12 functions per deployment, and every `api/*.js` file without a leading `_` is one function. Several public paths therefore share a function: `vercel.json` rewrites the path to its host with `?__route=<name>`, and `api/_dispatch.js` hands the untouched request to that route's handler. URLs, methods, auth and answers are the same as when each had its own file.

| Public path | Function | Handler |
|---|---|---|
| `/api/news` | `api/news.js` | `api/news.js` |
| `/api/refresh` | `api/news.js` | `api/_refresh.js` |
| `/api/listings` | `api/listings.js` | `api/listings.js` |
| `/api/checkout` | `api/listings.js` | `api/_checkout.js` |
| `/api/catalog` | `api/listings.js` | `api/_catalog.js` |
| `/api/orders` | `api/listings.js` | `api/_orders.js` |
| `/api/unsubscribe` | `api/unsubscribe.js` | `api/unsubscribe.js` |
| `/api/subscribe` | `api/unsubscribe.js` | `api/_subscribe.js` |
| `/api/submit` | `api/inbox.js` | `api/_submit.js` |
| `/api/advertise` | `api/inbox.js` | `api/_advertise.js` |
| `/api/alerts`, `/api/react`, `/api/newsletter`, `/api/stripe-webhook` | own file | own file |

To add a path without a new function, put its handler in an `_`-prefixed file, add it to a host's `host({...})` table and add the rewrite; `test/api-routes.test.js` checks the map and the function count (at most 9).

## Add feeds without editing code

In the Vercel project, add an environment variable `EXTRA_FEEDS` containing a JSON array:

```json
[{"id":"usi","name":"USI News","area":"Evansville","kind":"institution","url":"https://example.edu/feed"},
 {"id":"wcso","name":"Warrick County Sheriff","area":"Boonville","kind":"police","maxAgeDays":30,"url":"https://example.org/rss"}]
```

`kind` can be `institution`, `courts`, `police`, `events` or `obits`. Add `"geo": true` for outlets that cover a wider region, so only stories naming a local place are kept, and `"everyMin": 60` (minutes between fetches) for hosts that rate-limit. An entry whose `id` matches a built-in source is ignored. Redeploy after changing it.

## Features

Search, tabs in the top nav (News, the landing tab at `/`, which merges news outlets with Police & courts items in time order (those keep their no-photo rule and "not convicted" note), official Police & courts items have no tab of their own any more (`/police-courts`, `/police` and `/courts` redirect to `/`) and the boards; the old All tab and Liked page are gone, and `/all`, `/liked`, `/news`, `#all` and `?tab=all` all open News), "Show more" paging, hearts with counts, a breaking news card (only when an outlet labels a story "Breaking", "Just in" or "Developing story", for up to 12 hours), light/dark toggle, a refresh button, and a weather button that changes location (nine regional towns, or search any U.S. city). Active National Weather Service alerts for the chosen location show above the headlines.

## Shared heart counts (optional)

Hearts always work for the reader and are kept in their browser (they mark the heart filled; there is no Liked page any more). To make the counts shared across all readers, add the free **Upstash for Redis** integration to the Vercel project (Storage tab, Marketplace). It sets `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`, which `api/react.js` uses. Redeploy afterward. Without it, each story's count shows only your own heart (1 or nothing). One heart per browser per story; there are no accounts, so determined people can clear storage and heart again.

## How the news is fetched
A scheduled job calls `/api/refresh`, which fetches every feed, merges the stories and saves them in Redis. `/api/news` only serves that saved snapshot, so pages load instantly and never wait on a slow publisher.
- **Per-source memory:** each source keeps its last good stories (up to 80, within the age window). A failed or rate-limited fetch keeps them and marks the source `stale` in the `sources` list instead of making it vanish.
- **Conditional requests:** the ETag / Last-Modified from the last fetch is sent back, so unchanged feeds answer 304 and cost almost nothing. The URL that worked last time is tried first.
- **Two tiers:** `?tier=fast` (TV stations, daily papers, FBI and U.S. Attorney releases) every 10 minutes and `?tier=all` twice an hour.
- **Self-healing:** with no snapshot, or one older than 3 hours, the first visitor to `/api/news` triggers a refresh (guarded by a short lock). Without Redis the site works as before, fetching live when the hourly cache expires.

Setup (about five minutes):
1. Add the Upstash Redis integration in Vercel (see Shared heart counts) if you haven't.
2. Add an environment variable `CRON_SECRET` in Vercel (any long random string) and redeploy.
3. In this GitHub repo add the secrets `CRON_SECRET` (same value) and `SITE_URL` (for example `https://tristatenews.vercel.app`). The workflow in `.github/workflows/refresh-news.yml` then runs on schedule. You can also run it by hand from the Actions tab.
4. On Vercel Pro you can use Vercel Cron instead: add `"crons": [{ "path": "/api/refresh?tier=all", "schedule": "*/30 * * * *" }]` to `vercel.json`. On the Hobby plan Vercel rejects crons that run more than once a day, which is why the repo uses GitHub Actions.

Check it works: `curl -H "Authorization: Bearer $CRON_SECRET" "$SITE_URL/api/refresh?tier=all"` returns how many stories were stored, how many sources answered 304, and which sources are failing.

## Feed status (checked October 17, 2026)

- **Courier & Press and Henderson Gleaner** (Gannett) have no public RSS and answer automated requests with HTTP 402, so they come through Google News site searches (`gnews()` in `api/news.js`). Links open through news.google.com. Both are geo-filtered because Gannett feeds carry USA TODAY Network sports and shopping stories.
- **BLOX papers** (Messenger-Inquirer, The Messenger, Dubois County Herald, Washington Times-Herald, Sun-Commercial, WPSD, Princeton Daily Clarion, Daily Republican-Register) rate-limit shared cloud IPs (HTTP 429). They are polled at most hourly (`everyMin`), a host that answers 429/403 is left alone for 30 minutes (doubling up to 6 hours), and a Google News fallback fills in meanwhile. Wire and syndicated copy under `/news/national`, `/news/world`, `/sports/national`, `/lifestyles/health`, sister-paper paths and so on is dropped (`WIRE_PATH_RE`).
- **News feed hygiene:** obituaries (an `/obituar` path or "Obituary" in the title) never appear in News; local-outlet stories that name another state ("An 81-year-old Mississippi man...") and no place in the region are dropped as network copy; standing items like TOWN CRIER and CALENDAR are skipped.
- **Removed:** Pike County News (it is the Pike County, **Missouri** paper), Murphysboro American, WEOA and WJPS (dead hosts), Explore Evansville (no feed or iCal), Visit Owensboro (403 to automated requests), Washington Times-Herald obituaries (its feed only returns months-old notices).
- **Police & courts** items (shown in News; the separate tab was merged into it) come from **official sources only**: U.S. Attorney releases for S.D. Indiana (Evansville), W.D. Kentucky and S.D. Illinois, the three FBI field offices, the Vanderburgh County Sheriff and the Vanderburgh County Prosecutor (90 days; it posts rarely). Crime stories from news outlets, including the Eyewitness News crime section (a News source that adds crime stories its main feed has rotated out), stay in News. Policy (`safetyView()` in `api/news.js`): police and court cards never show photos (no mugshots), anything that mentions a juvenile (`JUVENILE_RE`: juveniles, teens, ages under 18, students) is dropped, and arrest-type items (arrested, charged, suspect...) from every Police & courts source (police, sheriff, prosecutor, U.S. Attorney, FBI) leave after 14 days and carry a "Charged or arrested, not convicted" note. Items whose headline reports an outcome (`OUTCOME_RE`: sentenced, convicted, pleaded guilty, acquitted) keep their source's window. Not used on purpose: jail rosters and booking lists, EPD's daily crime-report PDFs (names and home addresses of victims), MyCase and CourtNet (robots.txt forbids them), raw PACER docket feeds.
- Working feeds that often show nothing because of the regional filter: WTHI, WSTO, WIKY, Indiana Capital Chronicle, Kentucky Lantern, Capitol News Illinois, WKMS, Illinois Public Media.

## Events tab

The **Events** tab shows event cards (date tile, name, time, place, category) with category filters. Anyone can add an event (name, category, date, optional time and place, town, details, optional organizer contact) through `/api/listings?kind=event`; events come down the day after they happen, are rate-limited, reject links and are hidden after 3 reports. Upcoming items from any calendar feed (`kind: 'events'` sources in `api/news.js`, RSS or iCal) are merged into the same list. Until something is posted or a feed has upcoming items, the tab says so and offers to add an event.

## Deals tab

Local businesses can post a deal (business, offer, category, town, optional coupon code and end date, where to find it) from the Deals tab. Deals use the same `/api/listings` endpoint and Redis store as classifieds (`kind=deal`), come down on their end date or after 30 days, reject links, are rate-limited, and are hidden after 3 reports. The page shows deal cards only (no news stories). Without Upstash configured, the tab shows no deals.

## Classifieds tab

Readers can post items for sale (title, price, town, details, contact). Listings are stored in the same Upstash Redis as the heart counts, expire after 30 days, are rate-limited (3 a day per browser, 8 per IP), reject links, and are hidden after 3 reader reports. A poster can remove their own listing; set `LISTINGS_ADMIN_KEY` to remove any listing with `DELETE /api/listings?id=<id>` and an `x-admin-key` header. Without Upstash configured, the tab shows only links to other local boards. Contact details are public, so consider a short posting policy.

### Posting forms

Every community posting form (classifieds, deals, events, jobs, obituaries) has a required "I'm 18 or older, and I agree to the Terms of Use and Privacy Policy" checkbox, and `POST /api/listings` rejects a new post without `adult: true` (400, `field: "adult"`). The Submit news consent line includes the same 18+ statement.

There are no sample or demo posts: a board with nothing posted says so. Classifieds posts have a category, condition, price (or Free) and a phone or email that is checked; deals have a category, optional coupon code and end date. Both forms show inline errors, and each list has category filters.

## Photos and logos
Classifieds, Deals and Events posts can include a photo; Deals can also include a business logo. The form re-encodes uploads to JPEG in the browser (photo: 800px longest edge; logo: 96px square). `api/listings.js` accepts only real JPEG data, stores the photo under its own key and serves it at `GET /api/listings?img=<id>` (cached one day). Logos are stored inline in the post. Photos and logos are only saved when Upstash Redis is configured.
Posts without a photo show generated category art; businesses without a logo show an initials avatar. Events from feeds show their source's logo.

## Submit news page
The footer's "Submit news" button opens a submission form (type, headline, details, town, date, up to two photos, contact info, consent). `POST /api/submit` validates it, rate-limits 5 per IP per day, ignores bots via a hidden honeypot field, and delivers it by either or both of:
- **Redis:** stored in the `tsn:tips` list (latest 500). Read them with `GET /api/submit` and header `x-admin-key: <LISTINGS_ADMIN_KEY>`.
- **Email (Resend):** set `RESEND_API_KEY` and `TIPS_TO_EMAIL` (optional `TIPS_FROM_EMAIL`). Photos arrive as attachments and replies go to the submitter.
With neither configured the form says submissions aren't open yet. Edit the "Good to know" policy lines in `public/index.html` (`renderSubmit`) to match your newsroom's rules.

- **Obituaries** are the papers' own obituary sections (BLOX `c=obituaries` feeds for the Messenger-Inquirer, Dubois County Herald, Princeton Daily Clarion, Sun-Commercial and The Messenger) and the Owensboro Times, plus funeral homes (`funeralHome: true`):
  - FrontRunner `/rss.xml`: Ziemer and Browning (Evansville), Koehler (Boonville), Haley-McGinnis and James H. Davis (Owensboro), Nass & Son (Huntingburg).
  - Obituary sitemaps (`parser: 'sitemap'`): Benton-Glunt & Tapp (Henderson) and Becher & Kluesner (Jasper) on FuneralOne, Colvin (Princeton) on CFS, Doyle (Princeton), Glenn (Owensboro), Goodwin-Sievers and Duesterberg-Fredrick (Vincennes) on Tukios, Barnett-Strother (Madisonville) on Gather. Only the newest entries in the window are read, at most 6 new obituary pages per source per run, and pages read before are reused.
  - Each card is the name, a summary of at most 220 characters and a link to the full notice; no full text is copied. When a paper and a funeral home list the same person (matched on first and last name, ignoring nicknames, maiden names and middle names), the funeral home's card is kept, with the paper's summary if the funeral home has none.
  - Checked and left out: Fredrick & Son (Vincennes, 403 to automated requests), Harris Funeral Home Madisonville (robots.txt disallows all crawlers), Boone and Pierce (403).
  - They are kept for 21 days. The Courier & Press publishes through Legacy.com, whose terms forbid automated access, so Evansville is covered by the funeral homes above.
- **Weather banner**: current conditions from Open-Meteo, alerts from the National Weather Service API (`api.weather.gov`), both called from the browser and credited in the banner.
- **Breaking banner**: shows only stories the outlet itself labels breaking (see `BREAKING_RE`), for 12 hours, with the outlet name and a link.

- **Ticketmaster events** (concerts, sports, theater within 75 miles of Evansville): set `TICKETMASTER_API_KEY` (free key from developer.ticketmaster.com) in the Vercel environment variables and redeploy. Without it the source is skipped. The key is read on the server only and never stored with the feed data or sent to the browser.

## Jobs

The Jobs tab is a community board like Classifieds and Deals: employers post openings (title, employer, industry, town, full-time/part-time/seasonal/contract, pay, how to apply by phone or email, optional logo) through `POST /api/listings` with `kind: "job"`. Jobs expire after 45 days, can be reported (hidden at 3 reports) or removed by their poster, and are searchable with the rest of the site. The tab also links to Indeed, LinkedIn, the Indiana, Kentucky and Illinois state job sites and USAJOBS. Until real postings arrive it says nothing is posted yet. Public job feeds for the area were checked and none were available without an API key or login.

## Making money

- **Featured posts (Stripe).** Posters see a "Feature for N days · $X" button (or "Feature until Tue, Oct 20 · $X", see below) on their own job, deal, event or classified (job $99/30 days, deal $79/14, event $59/7, classified $19/7). Every price lives in `api/_catalog.js` in integer cents with a price version (`PRICE_VERSION`); checkout charges only those (the board is checked on the server, and any price the browser sends is ignored), records the version in Stripe metadata and `tsn:order:<session>` (30 days while unpaid; permanent once paid), and the page reads the same table from `GET /api/catalog` (served by `api/listings.js`). The catalog also lists Packages A–D ($249/$599/$1,199/$2,499 per 30 days; D by proposal), newsletter sponsorship ($199 / $699 for 4, off sale until every gate is met: 1,500 verified subscribers, measured deliverability, defined inventory, and approval; a dedicated email is by proposal), sponsored feature ($499) and creative ($99, waived on $599+ packages); none of those are purchasable online yet. To change a price, add a new `PRICE_VERSION` and keep the old table in `HISTORY`; posts already bought keep what they paid for. Featured posts sort first with an amber "Featured" badge. Set `STRIPE_SECRET_KEY`, and in Stripe add a webhook endpoint `https://<site>/api/stripe-webhook` for `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `charge.refunded` and `charge.dispute.created`, and set `STRIPE_WEBHOOK_SECRET` to its signing secret. Optional `SITE_URL` sets where Stripe returns people. Without the secret key the button is hidden. Pricing is created inline at checkout, so no Stripe products are needed.
- **Featured period.** One rule, in `public/featured.js`, used by the button, checkout and the webhook: the period starts now (or when the post's current Featured period ends) and lasts the catalog's days, except that an event, or a deal with an end date, is featured only until the end of that day (midnight Central), at the same price; the button and Stripe's page say "until <day>", and when less than a day would be added there is no button and checkout answers 409. Checkout sessions expire after an hour, so the period shown is the one applied. A classified, job or deal without an end date never loses paid time: when the period runs past the post's expiry, the webhook extends the post (and its photo and board entry) to the period's end plus a day. Purchases made before the catalog (no price version) keep exactly the days they bought.
- **Payments and refunds.** The webhook applies each payment first and marks the Stripe event processed last, so a failure answers 500 and Stripe's retry finishes the job; a repeat of an event, or a second event for the same session, changes nothing. It checks the amount and currency Stripe collected against the order and the catalog. Every outcome is kept in `tsn:order:<session>` with no expiry: `fulfilled`, `needs_refund` (the post was gone or its date had passed), `amount_mismatch`, `needs_review`, `payment_failed`, then `refunded` (a full refund ends the unused part of that order's Featured time), `partially_refunded` or `disputed`. Refunds and disputes for payments with no order are kept too. A post removed while Featured leaves a record: removed by reports or the admin, it goes on the attention list (the Terms owe the unused part back unless the post broke them); deleted by its poster, it is kept for reference. Refunds are made in the Stripe dashboard; nothing here sends money. Keys and statuses are listed at the top of `api/_orders.js`. Read them with `GET /api/orders` and header `x-admin-key` (`LISTINGS_ADMIN_KEY`), or on the admin page.
- **Sponsors.** Ads come only from advertiser creatives an admin approved (`api/_creative.js`, served at `/api/creative`; the page reads `/api/creative?live=1`). `public/sponsors.json` only documents the layout and ships with every value null; the page never reads ads from it. Places: a sponsor line at the top of each ad board (`jobs`, `deals`, `events`, `classifieds`; the News feed has none), side ads (tall, vertical units in the left and right margins, only on the Events, Jobs, Deals and Classifieds tabs, on screens 1360px wide and up; `TSNAds.railFill` decides; with samples on, an unsold margin on either side shows a vertical sample ad). The page widens on big screens (`--page-max`: 960px, 1040px from 1440px, 1120px from 1680px, 1240px from 1920px, 1360px from 2560px; side ads grow to 240px and 300px wide), and lists add columns there instead of stretching; and one in-listing ad card per board (`public/adslots.js` holds the rule: after the 6th post, or after the last post on a shorter board, none on an empty board, never in search results). Several ads in one place take equal 15-minute turns by the clock (`TSNAds.turn`), the same for every reader at the same moment. Every ad is labeled "Sponsored" and its link is `rel="sponsored"`. An open line or card, and an unsold right margin, shows the site's own house unit, labeled "Advertise with us" ("Your business here, advertise with Tri-State News"), which opens the advertising inquiry form; an unsold left margin stays empty. Our own ads are never targeted: every reader of a board sees the same ad, with no cookies, storage or reader data. One still image at most, no motion, pop-ups or sticky placement. News, Police & courts, Obituaries and Breaking have no ads.
- **Advertiser creatives.** An advertiser sends an ad at `/creative.html` (an image, a headline up to 60 characters, text up to 140, a button from a fixed list: Visit website, Shop now, Learn more, Call now, Get directions, and a destination). Uploading needs an inquiry reference (`AD-…`) with the email used on that inquiry, a paid order's checkout id (`cs_…`), or a signed link made in `/admin.html` (14 days; HMAC keyed by `CREATIVE_TOKEN_SECRET`, or derived from `LISTINGS_ADMIN_KEY` when that isn't set). The server checks: a still JPEG, PNG or WebP (by its bytes; animated PNG/WebP and GIF refused), 300 KB at most, 300×150 to 4000×4000 pixels; https only with no credentials, port, IP address or local host; no link shorteners, redirectors or another address inside the link; "Call now" takes a U.S. phone number (stored as `tel:+1…`) and "Get directions" a Google, Apple or Bing Maps or OpenStreetMap link. The destination is never fetched by the server. Up to 10 uploads per connection per day and 5 open creatives per reference. Every upload is stored as pending (Upstash, like listing photos, 60-day TTL); nothing is served until an admin approves it in `/admin.html` with a reason and its placements (`card:<board>`, `line:<board>`, `rail:left|right`). Approve, reject and withdraw each need a reason and are written to `tsn:cr:audit`. A pending or rejected image is served only with the admin key; rejected and withdrawn images are deleted. Fits Upstash's free tier (an image is ≤ 300 KB, about 400 KB as a data URL, well under the 10 MB request limit and the 256 MB store; approved images are cached by the CDN for an hour so readers rarely reach the store) and keeps the 8 functions (`/api/creative` is a rewrite to `api/inbox.js`).
- **Campaigns.** An admin books an approved creative in `/admin.html` → Campaigns: placements (only those the creative was approved for), a start and an end date (Chicago calendar dates, both inclusive) and a note. `api/_campaigns.js`, served at `/api/campaigns` (admin only; rewritten to `api/inbox.js`, still 8 functions). Inventory caps per placement per day: 3 shares for the in-listing card and 3 for the sponsor line on each board, 2 for each side ad (`CAPS`, from the packages plan); a booking that would go over on any day is refused with the placement and the day. A paused campaign keeps its share; ending one (a reason is required) frees the rest of its dates. Every create, pause, resume and end is in the campaign log. Serving is behind `ADS_CAMPAIGNS`: unset or anything but `on`, `/api/creative?live=1` keeps serving every approved creative on its approved placements; with `on`, only campaigns running today whose creative is still approved fill the spots, in a fixed order (start date, then id), each ad tagged with its campaign id. Sponsors sharing a spot take equal 15-minute turns by the clock (`TSNAds.pick`), the same for every reader at the same moment, so over a day each gets the same number of turns, give or take one. Nothing is targeted. Unsold spots still show a sample ad (if samples are on) or the house unit. To switch over: book a campaign for each approved creative that should keep running, then set `ADS_CAMPAIGNS=on`; unset it to roll back. Category exclusivity and sole-board holders (packages plan) aren't built: they need Sam's OK. Records have no expiry (sales records); the log keeps the latest 1,000 actions.
- **Ad counts.** First-party, cookie-free daily totals per campaign and placement (`api/_adstats.js`, `/api/adstats`, rewritten to `api/inbox.js`). A booked campaign's ad (it carries `cid` and `pl` from `/api/creative?live=1`) sends a `navigator.sendBeacon` with only `{e, cid, pl}`: `v` once per page load when at least half of it is on screen, `c` on a click. Samples, house units and ads served with `ADS_CAMPAIGNS` off are never counted. The server counts only with the flag on, for a campaign running today on that placement, skips obvious bots by user agent, and caps each connection at 600 events a day by a keyed one-way hash (HMAC with `ADSTATS_SECRET`, or a key derived from `LISTINGS_ADMIN_KEY`) of the address and the date (`tsn:as:rl:<hash>`, 24 hours); totals are in `tsn:adstat:<campaign id>`. The admin page shows counts by day for each campaign (Counts) and downloads them as CSV (Counts CSV). Quote only these measured counts to advertisers (docs/legal-review.md item 24).
- **The /advertise page.** Rates, packages, how our ads work and the inquiry form, in `data/pages/advertise.html` (outside `public/`, so it can't be reached around the flag) served by `api/_adpage.js` through the `/advertise` rewrite to `api/inbox.js` (`includeFiles: data/pages/**`; still 8 functions). Set `ADS_PAGE`: unset or anything else is off (`/advertise` redirects to `/#advertise`, which opens the site's Advertise form); `preview` serves it with `noindex` and no caching for review; `on` serves it indexable (add it to `sitemap.xml` then). Every price comes from `/api/catalog`: Featured posts with their days, Packages A–C with "Ask us", Package D "By proposal" with no price, and newsletter sponsorship, the sponsored feature and ad design as "Coming soon" (nothing on the page can be bought). The form posts to `/api/advertise` and shows the `AD-` reference used for `/creative.html`. The site's Advertise form links to the page only while `/advertise` answers 200.
- **Advertise page.** The footer "Advertise" button opens a rate card and inquiry form (`POST /api/advertise`), stored in Redis and emailed through Resend like news tips (`RESEND_API_KEY`, `TIPS_TO_EMAIL`). Read inquiries with `GET /api/advertise` and header `x-admin-key`.
- **Newsletter.** The signup box under the news feed posts to `/api/subscribe` and keeps emails in Redis (read with `GET /api/subscribe` and `x-admin-key`). Set `RESEND_AUDIENCE_ID` (with `RESEND_API_KEY`) to also add subscribers to a Resend audience for sending broadcasts. Readers unsubscribe themselves at `/unsubscribe.html` (linked in the footer), which posts to `/api/unsubscribe`: it removes the address from the set (and marks it unsubscribed in the Resend audience when configured), is rate-limited to 5 a day per connection, and gives the same answer whether or not the address was subscribed. For links in newsletter emails use `require('./api/unsubscribe.js').link(email)`, which adds an HMAC token keyed by `NEWSLETTER_SECRET` (falls back to `CRON_SECRET`); with a token the page unsubscribes on open, and the endpoint also accepts RFC 8058 one-click POSTs (`List-Unsubscribe=One-Click`, token required).
- **Admin page.** `/admin.html` (not indexed) takes your `LISTINGS_ADMIN_KEY` and lists newsletter subscribers (with a CSV download), advertising inquiries, news tips, and (read-only) Featured orders with the ones needing attention: refunds due, amount mismatches, disputes, partial refunds, and Featured posts that were removed.
- **Advertising leads.** In `/admin.html` each advertising inquiry has a status (New, Contacted, Proposal sent, Won, Lost, Spam), our notes and a history; a filter shows Open (all but spam), one status, or all, with counts, and an "Inquiry activity" list shows every change newest first (times in CT). The rules are in `api/_leads.js`; `GET /api/advertise` (admin) returns the latest 300 inquiries with their lead state, and `POST /api/advertise` with `x-admin-key` and `{action: 'status', ref, status, note?}` or `{action: 'note', ref, note}` changes one (only for an inquiry that exists; same status twice is refused; nothing in the history can be deleted). Stored in `tsn:lead:<ref>` (kept 400 days after the last change) and `tsn:lead:log` (latest 1,000 changes). Nothing here emails the advertiser: reply from your own inbox. An inquiry marked Spam can no longer be used as a `/creative.html` upload reference. The inquiry form on `/advertise` also asks, optionally, for a package (A–D) and a budget per 30 days; the budget bands come from `/api/catalog` `budgets`, cut at the package prices, and the server accepts only those keys. Both appear in the inquiry email to our inbox and in admin.
- **Google AdSense.** Not wired: its only placement was the News-feed sponsor line, which was removed. Adding it back needs a new placement, a privacy-policy update and consent handling first.
- **Placeholder sample ads.** While a spot on Jobs, Deals, Events or Classifieds has no approved ad, it can show a made-up business from `public/sponsors.json` `samples.ads` instead of the plain "Advertise with us" unit. One switch: `"samples": { "on": true }`; set it to `false` and every spot goes back to the house unit. Each sample is labeled "Sample ad", says it isn't a real business, links only to `/advertise` (the page sets the link; the file holds only a name and a line), and rotates by the Chicago date with different samples in the card, the sponsor line and the right side ad. A real, approved creative always takes the spot first. Samples follow the same placement rules as real ads: never on News, Police & courts, Obituaries or Breaking. The names were checked against a web search for existing businesses; change any that turn out to be real. `test/sample-ads.test.js` covers it, and `test/house-ads.test.js` still fails if sample posts, "Featured · Sample", the old made-up advertisers or invented offers come back anywhere else.
- **Ads on News.** News is one story per row at every width (from 1440px the column is capped at `--news-max`, 960px, and centered in the wider page so lines stay readable; other boards keep their columns). It gets an in-feed card (placement `card:news`, filled by a campaign or, while unsold, a sample; no house unit in the feed) about every 6th story, so at most one per screen. `TSNAds.newsSlots` never puts it first or last, and never directly before or after a Police & courts item (it moves down a story until both neighbours are clear). Breaking stays ad-free, search results get none, and News also gets the side rails. Obituaries still get no ads.
- **Ad sizes.** `public/adsizes.js` maps every placement to standard IAB units by screen width: News card 728×90 (768px and up) / 320×100 (phones), board cards 300×250, side ads 160×600 (1360–2559px) / 300×600 (2560px and up); the sponsor line stays text. Its CSS lays each size out from the image and words (picture areas use `object-fit: cover`, text is clamped, words hyphenate), and an approved creative can carry a finished banner per size (`sizes` on upload, served at `/api/creative?img=<id>&size=728x90`). The same module draws the previews on `/creative.html` (with crop and resolution warnings), `/advertise` and the site's Advertise panel. At 1440px the page is 1056px so 160×600 side ads fit; 120×600, 970×250 and 320×50 aren't used.
- **Obituary action row.** "Send flowers", "Plant a tree" and "Donate" sit together in one row pinned to the bottom of each obituary card (posted notices and feed cards), wrapping on phones and stacking under 375px, with 40px targets. "Plant a tree" uses a funeral home's `treeUrl` in `data/funeral-homes.json`, else `data/flowers.json` `tree.fallbackUrl` (One Tree Planted's Gift Trees In Memory page, unpaid, `rel="noopener nofollow"`); `TREE_AFFILIATE_ID` (or `tree.affiliateId`) plus a `tree.affiliateUrl` template would make it a "paid link" with `rel="sponsored noopener"`, both empty now. "Donate" uses a home's `donateUrl`, else shows only when the obituary asks for donations ("in lieu of flowers", "memorial contributions may be made to ..."): an https link in that sentence, else the obituary's own page; otherwise it is hidden (no invented charity). `GET /api/flowers` also returns `tree` and `donate`.
- **"Send flowers" on obituaries.** A quiet "Send flowers" text link under each obituary (feed cards and posted notices), never an ad unit. The rule is in `public/flowers.js`; the page reads `GET /api/flowers` (`api/_flowers.js`, rewritten to `api/listings.js`; still 8 functions). If the obituary's funeral home has a checked florist page in `data/funeral-homes.json` (`name` → `florist`, https only; every entry is empty until someone confirms the page on the funeral home's own site: don't guess URLs), the link goes there, unpaid. Otherwise, if an affiliate ID is set, it's the Florist One affiliate link, labeled "paid link" with `rel="sponsored noopener"`. Otherwise it goes to `data/flowers.json` `fallbackUrl`, Florist One's public funeral-flowers page (`https://www.floristone.com/funeral-flowers/`, checked with curl): no affiliate code, no "paid link" label, `rel="noopener nofollow"`, because nothing is earned. Set `fallbackUrl` to `""` and, with no florist page and no ID, there's no link. Set the ID in the server env var `FLORIST_ONE_AFFILIATE_ID` (wins) or `data/flowers.json` `affiliateId`; both are empty, so today every obituary links to the fallback. The link shape in `data/flowers.json` comes from Florist One's published affiliate links; replace it with the exact link from its affiliate area after joining (TODO there). `test/flowers.test.js` covers it.
- **Funeral-home obituaries.** The Obituaries tab has a "Post an obituary" form for funeral homes and families (name, funeral home, town, service date and place, short tribute, phone or email). Posts show above the newspaper obituary feed, expire after 30 days, can be reported or removed, appear in search. Obituaries are always free: there is no paid featuring for them. There are no sample obituaries.
